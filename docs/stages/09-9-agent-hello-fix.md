## Цель простыми словами

В активной переписке менеджер может сразу писать по делу, без приветствия. Оценка не падает. Приветствие проверяем только когда это уместно.

**Готово когда:** ответ посреди живой ленты без «здравствуйте» не даёт замечания про приветствие; первое письмо клиенту, письмо после паузы ≥ 8 часов и ответ на клиентское «здравствуйте» — по-прежнему могут штрафовать, если приветствия нет. Сленг («ок ща») орёт как раньше.

## Правило (сначала §9.1, потом код)

Приветствие **ожидается**, только если выполнено **хотя бы одно**:

1. Менеджер отвечает на **первое** входящее клиента в этой ленте (это первый исходящий менеджера в разговоре).
2. Перед этим исходящим в ленте простой **больше 8 часов** (разница `sentAt` предыдущего сообщения любой стороны и текущего исходящего).
3. **Последнее входящее** клиента перед этим ответом само содержит приветствие (код, не модель: «здравствуйте», «добрый день/утро/вечер», «привет» в начале или как обращение).

Иначе приветствие **не** проверять: не писать в `issues`/`hint`, не снижать `businessStyle` только из‑за его отсутствия.

Прощание, сленг, грамотность — не тема этого этапа. Правило 09-1 (все критерии ≥ 4 → нет карточки) оставить.

**Код владеет флагом**, не модель: модель врёт про «каждое письмо должно начинаться с приветствия». Считать `greetingExpected` по сообщениям ленты, передать в user-prompt, после JSON вычистить приветственные придирки, если флаг ложный.

Для пункта 1 не хватает последних 6 сообщений: смотреть **всю** ленту (хотя бы «есть ли уже исходящее раньше этого»). Для паузы достаточно предыдущего `sentAt`. Для пункта 3 — последнее inbound перед этим outbound.
