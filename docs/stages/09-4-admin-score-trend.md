## Цель простыми словами

На графике «Динамика оценки» главный выбирает масштаб: каждая оценка, средняя за час или средняя за день. По умолчанию — каждый ответ, чтобы сегодняшний прогон был виден точками, а не одной.

**Готово когда:** на админке за сегодня видно несколько точек при масштабе «Ответы»; «Дни» по-прежнему одна точка за сутки; формулы AVG не сломаны.

## Правило (закрыть в архитектуре, потом код)

Сначала патч [§10.3](../../ARCHITECTURE.md#103-admin-только-chief), потом API и график.

- `GET /api/admin/stats` добавляет `charts.overallSeries`: `{ at, overall }[]` по `quality_scores.createdAt` по возрастанию. Поле `overallByDay` оставить (среднее за календарный день, пояс `Europe/Moscow`).
- Масштаб на клиенте, без нового запроса: `reply` (точка = оценка), `hour` (AVG за час Москвы), `day` (AVG за день Москвы).
- Переключатель на карточке: «Ответы» / «Часы» / «Дни». По умолчанию «Ответы».
- Формулы §10.3 (`AVG(overall)`, доля подсказок) не трогать.

Не RAG. Не отдельный endpoint. Не кислотные градиенты.

## Ручная проверка (нужна)

Модель не обязательна. Войдите как Игорь Белов, `http://127.0.0.1:3010/admin`.

1. «Динамика оценки», масштаб **Ответы** — несколько точек за сегодня, не одна.
2. **Часы** — точки по часам (сегодняшние ответы могут схлопнуться в 1–2 часа).
3. **Дни** — как раньше, одна точка `18.08` (или текущая дата).
4. Средние в карточках отдела и таблице менеджеров те же, что до правки.
5. Напишите агенту: видны ли отдельные ответы и не «поехала» ли вёрстка.
