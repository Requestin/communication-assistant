## Цель простыми словами

На каждое «Подобрать решение» заявка = текущие слоты этой ленты. Поздняя явная правка города, дат или числа людей побеждает; не упомянутое в этом письме слот **сохраняется**. Чего в переписке не было никогда — дырка: карточка менеджеру, SQL не запускать.

Одному человеку, если на все ночи нет `standard`, но есть `twin` — пакет с `twin`. В сиде 7 или 8 отелей на город; короткий заезд чаще находит номера, длинный всё ещё может честно сказать «нет».

**Готово когда:** «2 человека, Москва–Питер, 10–15» затем «даты на 12–17» даёт поиск на 12–17 с теми же людьми и городами; «один человек, Москва–Питер» без дат — совет уточнить даты, без пакета рейсов; одиночке с дырой в standard приходит twin; три известных длинных заезда ниже по-прежнему «нет номеров»; ответ без «Питер» в теле не штрафуют за «Питер» в теме.

## Правило слотов (закрыть в архитектуре, потом промпт и код)

Сначала патч [§9.2 шаг 1](../../ARCHITECTURE.md#92-агент-подбора-командировки), потом `travel-extract-system.md` и `processSuggestTravel`.

На вход по-прежнему все письма **этой** темы (`buildThreadPrompt`, хвост ~8000 символов). Карточки прошлых подборов (`AiNote`) в промпт **не** класть.

Слоты: `origin`, `destination`, `dateFrom`, `dateTo`, `people`.

- Читать ленту по порядку. Слот меняется, только если его **явно** поправили. Остальные живут дальше.
- Не выдумывать значения, которых не было в письмах.
- `people`: последнее явное число; если ни разу не звучало — **1** (как сейчас в §9.2).
- `needReturn` / `needHotel` по-прежнему из дат («с … по …»), отдельно не допрашивать.
- Города после модели резолвить кодом (`Питер` → LED). Нет в справочнике — как сейчас, «не найден город», это не дырка слота.

Обязательны для SQL: оба города нашлись в справочнике, есть `dateFrom` и `dateTo`. Иначе карточка менеджеру со списком дырок, пакеты пустые.

В JSON разбора добавить `missing` (массив имён слотов: `origin` / `destination` / `dateFrom` / `dateTo`). `unresolved` не смешивать с дырками: там по-прежнему сырые города, которых нет в `City.aliases`.

Не копить заявку в новой таблице. Не смотреть «только последнее письмо». Не RAG и не tools.
