## Цель простыми словами

В базе появляются выдуманные, но широкие справочники: крупные города России, рейсы и наличие номеров с 18.08.2026 по 31.12.2026. ИИ на этом этапе ещё нет.

**Готово когда:** в базе десятки тысяч рейсов, скрипт сида зелёный, инвариант «Москва–Петербург, 1–5 сентября, двое» выполняется.

## Автопроверки

```bash
npm run lint
npm test
docker compose up -d db
npx tsx scripts/seed-travel.ts
```

Ожидания:

- `flights` порядка 25–40 тысяч строк (ориентир §12.1).
- `hotel_availability` порядка 20–30 тысяч (ориентир этапа 1). С [09-3](09-3-travel-agent-upgrade.md) — около 45 тысяч при 7–8 отелях на город.
- 22 города.
- Инвариант: ≥3 рейса MOW→LED на 2026-09-01 с `seatsLeft≥2`; ≥3 рейса LED→MOW на 2026-09-05 с `seatsLeft≥2`; ≥1 отель LED с `twin.roomsLeft≥1` на ночи 01–04.09.2026.
- Повторный запуск без `--force` не переписывает данные и завершается успешно.
- `GET` debug отдаёт несколько рейсов на 2026-09-01 MOW–LED.

## Ручная проверка

**Экран смотреть не просим.** Если человек хочет проверить глазами:

1. `docker compose exec db psql -U commassist -d commassist -c "SELECT COUNT(*) FROM flights;"`
2. `curl -s 'http://127.0.0.1:3010/api/debug/flights?from=MOW&to=LED&date=2026-09-01'` — в ответе есть рейсы, цен в письмах никому не обещаем как настоящие.

## Что попросить человека

- Если сид не стартует из-за отсутствия `.env` / БД — те же шаги, что на этапе 0.
- Если заливка идёт дольше нескольких минут и хочется прервать — напишите; агент не должен оставлять полузалитую базу без `--force` плана очистки.
