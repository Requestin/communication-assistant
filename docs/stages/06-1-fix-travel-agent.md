## Зачем этот этап

После кода этапа 6 на стенде всплыли три отдельные проблемы. Арифметика и отказ по Томску в коде были верными; ломались UX суммы, доставка нового IMAP-письма и модель «один клиент = одна лента».

| Что видел человек | В чём была причина | Что сделали |
| --- | --- | --- |
| Сумма Петербурга «не сходится на глаз» | В справочнике цена рейса **за один билет**. Для двоих код считал `рейс × 2 + отель`, а в карточке стояла цена одного билета рядом с итогом за двоих | Формулу не меняли. В лейбле рейса: `6900 ₽ × 2 чел. = 13800 ₽`, под итогом строка сложения, пометка «билет × люди» |
| Письмо «Командировка Томск» не появилось в UI, хотя лежало в Gmail | Воркер с `disableAutoIdle` не делал повторный SELECT: stale mailbox, SEARCH/FETCH не видели новый UID | Перед каждым поллом `mailboxClose` + новый SELECT; fetch диапазона `lastUid+1:*`, если `uidNext > lastUid+1` |
| Томск и Петербург от одного клиента оказались в одном чате | Unique `(managerId, clientId)` — одна лента на email | Человек явно сказал: **разные темы = разные диалоги**. Сначала патч §7.4 / §8.3, потом схема `threadKey` |

**Готово когда (уже подтверждено человеком):** новая карточка Петербурга подробно показывает рейсы, отель и сумму; Томск — «Не найден город: Томск»; письмо про Томск видно отдельной лентой.

## Что внесли (чеклист — всё сделано)

### Сумма в карточке, формула та же

- [x] `packageTotalRub` по-прежнему `рейс_туда × люди + рейс_обратно × люди + отель за ночи`. Модель `totalRub` не пишет.
- [x] В `validateTravelPackage` в payload: `people`, `outboundSeatRub`, `returnSeatRub`, `hotelCostRub`.
- [x] Лейбл рейса при `people > 1`: цена билета × число человек = стоимость мест.
- [x] Под итогом строка вида `13800 + 15800 + 39500 = 69100 ₽` (пример с живого стенда: `6900×2 + 7900×2 + 39500`).
- [x] Пометка: цена рейса — за билет, в сумме умножается на людей; отель — за проживание на все ночи.
- [x] Кнопка «вставить в ответ» копирует уже эти подробные лейблы.

### IMAP: новые письма после курсора

- [x] Перед поллом закрыть выбранный mailbox и снова `SELECT INBOX`. Иначе imapflow держит снимок, а Gmail при `disableAutoIdle` не пушит новые UID.
- [x] Если `uidNext > lastUid + 1` — `FETCH` диапазона `newMailUidRange(lastUid)` (`5:*` при `lastUid=4`), не полагаться на SEARCH по stale-ящику.
- [x] Тест `newMailUidRange`: `4 → 5:*`, `0 → 1:*`.
- [x] Тела писем и пароли в логах по-прежнему резать (`safeError`, `clipBody`).

Типичный сбой, который это закрывает: курсор Анны `lastUid=4`, в INBOX уже UID 5 «Командировка Томск», UI пустой, пока воркер не переоткроет mailbox.

Сначала архитектура, потом код. Закрытое «не выдумывать схему» не ломали: unique клиента `(managerId, email)` как был.

- [x] Prisma: `Conversation.threadKey`; unique `(managerId, clientId, threadKey)`; индекс `(managerId, clientId)`. Миграция `prisma/migrations/20260818040400_conversation_thread_key/` (на стенде 5433 уже применена).
