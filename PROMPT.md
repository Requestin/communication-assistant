Проект: “Помощник в коммуникации с клиентами”
Ссылка на мой Github репозиторий данного проекта: https://github.com/Requestin/communication-assistant

Что делаем: Веб-сервис для менеджеров по работе с клиентами со встроенным ИИ-функционалом.

Описание:

Компания предоставляет услуги другим компаниям по оформлению командировок сотрудникам.

Примерный кейс: менеджеру на почту пишет клиент “нужно оформить командировку для двух сотрудников в Санкт-Петербург из Москвы с 01.09 по 05.09 ”, менеджер берет заявку в работу, подбирает билеты на самолет и номер в гостинице и скидывает клиенту.
6
Менеджеры общаются с клиентами по почте (у менеджеров почтовые ящики Gmail).

У каждого менеджера есть своя страница в сервисе, где он может работать с клиентами. На этой странице есть список клиентов и история переписки с каждым из них (автообновляемая при получении/отправке новых сообщений).

Есть главный менеджер, который оценивает качество общения с клиентами.

Необходимо встроить ИИ функционал в работу менеджеров:

ИИ должен помогать менеджерам оценивать общение с клиентами по определенным критериям в фоновом режиме (менеджер ответил клиенту - ИИ сразу автоматически без команды оценивает его ответ) и дает подсказки прямо в истории переписки (видимые только для менеджеров и главного менеджера), если какие-либо параметры ответа не соответствовали критериям.
У главного менеджера есть отдельная страница (админка) со статистикой по работе каждого менеджера, на которой видно клиентов каждого менеджера и статистику от ИИ по качеству общения с клиентами (также должна быть общая статистика по каждому менеджеру и в целом по отделу, то есть по всем менеджерам вместе)
По запросу (нажатию кнопки) ИИ должен помогать менеджеру подбирать наилучшие решения для клиентов исходя из запроса и информации, хранящейся в базах данных. Есть две базы: рейсы самолетов и наличие номеров в гостиницах. ИИ должен подобрать наиболее подходящее по срокам и стоимости комплексное решение и передать информацию менеджеру прямо в истории переписки (видимые только для менеджеров и главного менеджера)

Это пилотный проект для небольшой предварительной демонстрации, а не коммерческая разработка, решения должны быть условными - просто чтобы можно было показать как это может работать в принципе.

Подключать реальные базы данных для рейсов и гостиниц не нужно.
Достаточно сымитировать эти две базы (создать самостоятельно) и наполнить придуманными рандомными условно подходящими значениями.

Почтовые ящики нужно подключить по API, чтобы сервис мог получать историю переписки с каждым клиентом с почты каждого менеджера. Почтовые ящики тоже тестовые, а не реальные, их я создам самостоятельно.

В моем видении ИИ функционал должен обеспечиваться двумя ИИ-агентами:

Первый агент для оценки качества диалога с клиентом - простой агент с системным промптом, в котором прописаны критерии для оценки качества (для теста пусть будет грамотность, орфография, пунктуация и соблюдение делового стиля общения, можно найти правила в интернете и взять оттуда, можно придумать условные правила самостоятельно).

Второй агент для подбора решений из баз данных - не знаю как правильнее его технически реализовать. Тоже простой агент, который сам будет лазить по обычной базе данных? Или надо например реализовать RAG? На твое усмотрение.

У главного менеджера должна быть админка со статистикой менеджеров (цифры + визуал).

Некоторые условия:

1. Сроки минимальные, нужно быстро прототипировать и показать пилот просто для демонстрации теоретической возможности, а не как готовое продакшен решение
2. Менеджеров для теста будет трое. Клиенты и письма от них будут симулироваться вручную (буду просто сам вручную писать письма менеджерам на почтовые ящики)  только для демонстрации - думаю будет не больше 5-10 писем каждому менеджеру. 
3. Масштабирование не требуется
4. Сервис работает локально на сервере, в том числе ИИ функционал (локальная opensource модель), без облаков,  думаю было бы неплохо завернуть в Docker контейнеры (kubernetes не нужен)
5. Обновлять списки сообщение лучше мгновенно, если это не слишком сложно реализовать. Если слишком сложно, то достаточно и раз в минуту/пол минуты.

Мои предложения по стеку и техническим решениям (необязательные, просто мое видение - можешь предложить свои):

Frontend (UI): Next.js 15+ (App Router) + shadcn/ui. shadcn/ui даст красивые, современные компоненты "из коробки", а Next.js обеспечит быструю разработку.

Backend (API): Next.js API Routes. Для пилотного проекта мне кажется этого более чем достаточно. Пишем весь бэкенд на TypeScript в одном репозитории - это сильно ускорит разработку.

Database: Supabase (PostgreSQL). Бесплатный облачный сервис, который даст готовую БД, аутентификацию и, что важно, Realtime-подписки для мгновенного обновления интерфейса. Альтернатива: использовать SQLite, с обновлением страницы раз в 30 секунд (или по кнопке «обновить») - этого для демо достаточно, а реализация проще и ручной реализацией авторизации - сделать фиктивный вход без пароля или через простую форму, которая выбирает менеджера из списка (для пилота это допустимо).

AI Model: В качестве ИИ-модели предлагаю использовать новую Qwen 3.8 27b - у нее открытые веса, лежат на HF, либо можно попробовать модель попроще - на твое усмотрение (например, 7b).

Email Integration: IMAP-протокол. Самый простой и надёжный способ для чтения писем с Gmail-почты.

Важные дополнения к реализации

Сборка в Docker: Для лёгкого деплоя, давай обернем все компоненты в Docker-контейнеры. Будем использовать docker-compose для их совместного запуска.

Мгновенное обновление (Real-time): если решим использовать Supabase. Когда наш бэкенд (Next.js) получает новое письмо или AI-оценку и сохраняет её в БД, Supabase может автоматически отправлять событие на фронтенд через WebSocket. Это позволит обновлять историю переписки без перезагрузки страницы.

Красивый UI: Используем shadcn/ui. Это не просто библиотека, а набор переиспользуемых компонентов, которые вы копируете в свой проект и полностью контролируете. С ними вы сможете быстро собрать профессионально выглядящий интерфейс для менеджеров и админки.
